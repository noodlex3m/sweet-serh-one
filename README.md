# 🍰 sweet-serh-one — Оптово-роздрібний склад солодощів

[![Project Status: Under Development](https://img.shields.io/badge/Project%20Status-Under%20Development-orange.svg)](#)
[![Netlify Status](https://img.shields.io/badge/Netlify%20Deployment-Live-success.svg)](https://sweet.serh.one)
[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)

Сучасний, швидкий та адаптивний інтернет-магазин та оптово-роздрібний склад кондитерських виробів у Чернівцях. Проєкт розроблено на стеку **React + TypeScript + Vite** з використанням бази даних **Firebase Firestore** та стилізацією на чистому **Vanilla CSS**.

---

## 🚀 Що вже реалізовано (Поточний функціонал)

### 📁 1. Маршрутизація та структура сторінок
* Інтегровано `react-router-dom` для безшовної навігації.
* **Сторінки проєкту:**
  * `/` — Головна вітрина магазину з каталогом товарів.
  * `/account` — Особистий кабінет покупця.
  * `/admin` — Панель адміністратора (доступна лише для адміністратора).

### 📦 2. Каталог та Робота з товарами
* **Пагінація:** список товарів поділений на сторінки (по 12 товарів), з автоматичним скиданням на 1-шу сторінку при зміні категорії чи пошуку.
* **Пошук та фільтрація:** миттєва фільтрація за категоріями та пошуковим запитом (за назвою або SKU).
* **Інтерактивний Lightbox:** клік по зображенню товару відкриває модальне вікно на весь екран із повним збереженням пропорцій.
* **Кешування Firestore (`localStorage` Caching):** завантаження товарів кешується на **1 годину**. Це знижує кількість запитів до Firestore практично до нуля та забезпечує миттєве завантаження. Кеш автоматично скидається при діях адміна.

### 👤 3. Особистий кабінет та Оформлення замовлень
* **Авторизація:** вхід через Google або за допомогою Email/Password.
* **Профіль користувача:** збереження контактних даних (ПІБ, телефон, адреса, додаткові контакти: Telegram, Viber, WhatsApp). Дані автоматично підставляються в кошик при оформленні.
* **Мої замовлення:** перегляд історії замовлень, відстеження статусів у реальному часі та можливість **скасувати замовлення** самостійно, якщо воно ще має статус "Нове".

### 💼 4. Панель управління (Адмінка)
* **Каталог CRUD:** можливість створювати нові товари, редагувати опис, ціни, наявність та категорію, або видаляти товари.
* **Керування замовленнями:** перегляд усіх замовлень користувачів у реальному часі зі зміною статусів.
* **Seed каталог:** кнопка для швидкого завантаження 20 стартових товарів у порожню базу.

### 🔒 5. Безпека та Оптимізація
* Безпечні правила доступу в `firestore.rules` (захист даних профілів та замовлень від сторонніх очей).
* Перенесення приватних ключів у `.env` змінні.
* Виправлення помилок типізації TypeScript та ESLint конфігурації.
* Повна адаптація під мобільні екрани (Header та Hero-секции).

### 🌐 6. Деплой та Хостинг (Netlify)
* Налаштовано безперервну інтеграцію (CI/CD) з автоматичним деплоєм після кожного комміту в гілку `main`.
* Прив'язано та захищено персональний домен другого рівня **[https://sweet.serh.one](https://sweet.serh.one)** з автоматичним перенаправленням на безпечне з'єднання HTTPS (Let's Encrypt SSL).
* Усі приватні API-ключі безпечно перенесено в змінні оточення (Environment Variables) панелі Netlify.

### 🚚 7. Безпечна інтеграція з API Нової Пошти (Serverless)
* Запити до API Нової Пошти повністю перенесені на серверний рівень за допомогою **Netlify Serverless Functions** (`netlify/functions/nova-poshta.ts`).
* Секретний ключ `VITE_NOVAPOSHTA_API_KEY` повністю прихований від клієнта — він безпечно зберігається у змінних оточення Netlify і більше не компілюється у клієнтський бандл.
* Запити проксуються через відносний шлях `/.netlify/functions/nova-poshta` на нашому власному домені, що запобігає будь-яким проблемам із CORS.

### 🎨 8. Унікальний Favicon сайту
* Створено та встановлено сучасний логотип-іконку у вигляді шматочка торта в [index.html](index.html) (файл [public/favicon.png](public/favicon.png)), замінивши стандартну іконку Vite.

### 🔍 9. SEO-оптимізація та Google Search Console
* Налаштовано динамічне керування назвами вкладок браузера (`<title>`) та мета-описами сторінок (`<meta name="description">`) на базі вбудованого функціоналу **React 19** без сторонніх бібліотек.
* Службові та приватні розділи (`/account`, `/admin`) закриті від пошукових ботів за допомогою тегів `noindex, nofollow` та інструкцій у [public/robots.txt](public/robots.txt).
* Створено карту сайту [public/sitemap.xml](public/sitemap.xml) для індексації публічного каталогу, успішно додано піддомен та надіслано карту сайту в Google Search Console.

### 📱 10. PWA (Progressive Web App)
* Інтегровано плагін `vite-plugin-pwa` для генерації Service Worker, що кешує статичні ресурси додатку для роботи в офлайн-режимі.
* Створено іконки [public/icon-192.png](public/icon-192.png) та [public/icon-512.png](public/icon-512.png) та заповнено Web App Manifest, що дозволяє користувачам встановлювати сайт як нативний мобільний або десктопний додаток.

### 🛍️ 11. Гнучке керування цінами (Опт / Роздріб) та PDF рахунки-фактури
* **Налаштування гурту:** додано поля `wholesalePrice` та `wholesaleMinQty` в опис товару, що дозволяє продавати товари за зниженою оптовою ціною при досягненні заданої кількості.
* **Автоматичний кошик:** ціни перераховуються миттєво в кошику, закреслюючи роздрібну вартість, показуючи бейдж `Опт` та відображаючи сумарну економію клієнта.
* **Генерація PDF-рахунків на оплату:** інтегровано printable-компонент [Invoice.tsx](src/pages/Invoice.tsx) з генерацією специфікації товарів за оптовими цінами та автоматичним перекладом фінальної суми словами українською мовою.
* **Редагування замовлень адміном:** адміністратор може коригувати склад товарів у замовленні клієнта з автоперерахунком сум та наявністю міток `ОПТ` у списку замовлень.
* **Інтеграція в Telegram:** Telegram-сповіщення повністю узгоджені з оптовою ціною, відображають мітку `🏷️ (ОПТ)` на відповідних товарах та виводять рядок `🎁 Заощаджено на опті`.

### 🎨 12. Модульна стилізація (Style Cleanup)
* Повний рефакторинг та очищення інлайн-стилів (`style={{...}}`) із TSX-файлів сторінок.
* Створено окремі CSS-файли для кожної сторінки: [Home.css](src/pages/Home.css), [Account.css](src/pages/Account.css), [Admin.css](src/pages/Admin.css) та [Invoice.css](src/pages/Invoice.css), забезпечивши чистий розділ логіки та дизайну і професійну презентацію проєкту.

## 🛠️ Як запустити проєкт локально

1. **Клонувати репозиторій**:
   ```bash
   git clone https://github.com/noodlex3m/sweet-serh-one.git
   cd sweet-serh-one
   ```

2. **Встановити залежності**:
   ```bash
   npm install
   ```

3. **Налаштувати змінні оточення**:
   Створіть у корені файл `.env` на основі наявного файлу `env`:
   ```env
   VITE_FIREBASE_API_KEY=ваш_ключ
   VITE_FIREBASE_AUTH_DOMAIN=ваш_домен
   VITE_FIREBASE_PROJECT_ID=ваш_ід
   VITE_FIREBASE_STORAGE_BUCKET=ваш_бакет
   VITE_FIREBASE_MESSAGING_SENDER_ID=ваш_ід_відправника
   VITE_FIREBASE_APP_ID=ваш_ід_додатка
   ```

4. **Запустити сервер розробки**:
   * **Варіант А (Тільки фронтенд):**
     Якщо вам не потрібно тестувати автозаповнення Нової Пошти локально:
     ```bash
     npm run dev
     ```
   * **Варіант Б (Повне середовище із Serverless-функціями):**
     Щоб перевірити роботу автозаповнення доставки через локальний сервер-емулятор Netlify:
     ```bash
     npx netlify dev --offline
     ```
     *(Зверніть увагу: для роботи функцій локально у вашому файлі `.env` повинен бути прописаний дійсний `VITE_NOVAPOSHTA_API_KEY`).*

5. **Зібрати production-версію**:
   ```bash
   npm run build
   ```

## 📚 Корисне навчання (TypeScript & React)

При розробці цього проєкту ми звертаємо увагу на такі ключові концепції:
* **Типізація у TypeScript (`src/types/index.ts`)**: Опис суворих інтерфейсів для `Product`, `CartItem` та `Order` допомагає уникнути логічних помилок при передачі даних між компонентами.
* **Правильний розподіл файлів React Fast Refresh**: Експорт компонентів та хуків з одного файлу може блокувати HMR (гаряче перезавантаження). Для контекстів ми використовуємо директиву `/* eslint-disable react-refresh/only-export-components */` або розділяємо файли.
* **Оновлення стану під час рендерингу**: Замість виклику `setState` в `useEffect` для синхронізації пропсів, React дозволяє коригувати стан під час рендеру шляхом порівняння з попереднім значенням (як реалізовано в `Home.tsx` для скидання сторінки).

## ⚙️ Налаштування Telegram-сповіщень про замовлення

Для запуску сповіщень у приватну групу складу:
1. **Створення бота:**
   * Знайдіть у Telegram бота **`@BotFather`** та надішліть команду `/newbot`.
   * Отримайте токен бота (`TELEGRAM_BOT_TOKEN`), наприклад: `123456789:ABCdefGhIJKlmNoPQRsTuvWxYz`.
2. **Створення приватної групи:**
   * Створіть нову групу в Telegram (наприклад, *"Замовлення sweet-serh-one"*).
   * Додайте створеного бота у групу та зробіть його адміністратором (з правами надсилання повідомлень).
3. **Отримання ID чату (`TELEGRAM_CHAT_ID`):**
   * Додайте у групу бота **`@RawDataBot`** або **`@my_id_bot`**, щоб дізнатися ID групи (він зазвичай починається з `-100` для супергруп, наприклад: `-1001234567890`).
   * Видаліть допоміжного бота з групи після отримання ID.
4. **Налаштування змінних:**
   * Додайте отримані `TELEGRAM_BOT_TOKEN` та `TELEGRAM_CHAT_ID` до кабінету керування Netlify у вкладку **Environment Variables** (для безпеки даних).
